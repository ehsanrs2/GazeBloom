# GazeBloom — استفاده آزمایشی از تشخیص Idle در Ubuntu

**این قابلیت فقط عدم فعالیت ورودی کاربر را می‌سنجد.** هیچ راهی ندارد که بفهمد کاربر در حال نگاه‌کردن به نمایشگر، کتاب‌خواندن، فیلم‌دیدن، یا استراحت واقعی است. اثر درمانی چشم هم سنجیده نمی‌شود.

## فعال‌سازی اختیاری

```bash
cd /home/ai/project/My/GazeBloom
git pull --ff-only
uv sync --python /usr/bin/python3 --no-managed-python --locked
# هنگام آزمایش:
uv run --python /usr/bin/python3 --no-managed-python --locked \
  python -m gazebloom --interval-min 1 --idle-aware --idle-threshold-sec 60
```

برای اجرای عادی، بدون `--idle-aware` برنامه مانند نسخه قبل یک تایمر دستی است.

بعد از ۶۰ ثانیه عدم فعالیت ماوس/صفحه‌کلید، اگر برنامه در وضعیت «کار» یا «اعلان منتظر پاسخ» باشد، شمارش زمان به‌صورت خودکار موقتاً مکث می‌کند؛ پس از بازگشت ورودی کاربر، فقط **مکث خودکار خودش** را برمی‌دارد. مکث دستی هرگز به‌صورت خودکار لغو نمی‌شود. زمان وقفه ۲۰ ثانیه‌ای کاربر همچنان مستقل پیش می‌رود.

## تشخیص نوع جلسه و پیش‌نیازها

```bash
echo "$XDG_CURRENT_DESKTOP"
echo "$XDG_SESSION_TYPE"

# در GNOME ممکن است سرویس زیر در دسترس باشد:
gdbus call --session \
  --dest org.gnome.Mutter.IdleMonitor \
  --object-path /org/gnome/Mutter/IdleMonitor/Core \
  --method org.gnome.Mutter.IdleMonitor.GetIdletime

# در نشست X11، یک مسیر جایگزین:
sudo apt install xprintidle
xprintidle
```

روش GNOME به D-Bus جلسه کاربر اتکا می‌کند و نیازمند اجرای دستورات با sudo نیست. در X11 در صورت شکست GNOME D-Bus، `xprintidle` استفاده می‌شود. در KDE Wayland یا دسکتاپ‌های دیگر، اگر سرویس پشتیبانی نشده باشد، پیام **Idle status unavailable** نشان داده و زمان‌بند قبلی ادامه پیدا می‌کند.

گزینه `--idle-aware` به‌صورت پیش‌فرض خاموش است؛ هیچ داده خامی از صفحه‌کلید یا ماوس ذخیره نمی‌شود. در صورت انتخاب مستقل `--log`، تنها رویدادهای مکث/ادامه با برچسب `source=idle_monitor` به فایل محلی افزوده می‌شوند.

## نکات مهم تجربی
- مدت «فعال» در این نسخه، زمان فعالیت واقعی چشم و حتی زمان دقیق کار با مانیتور نیست.
- Idle هنگام خواندن یک مطلب طولانی یا تماشای ویدئو می‌تواند زیاد شود، حتی وقتی فرد هنوز صفحه را می‌بیند.
- این نسخه ممکن است در محیط‌های Wayland غیر GNOME نتواند Idle را تشخیص دهد.
- اگر سرویس سیستم یا اتصال D-Bus موقتاً شکست بخورد، وضعیت به unknown تغییر می‌کند؛ مکث خودکار سابق تا مشاهده معتبرِ فعالیت باقی می‌ماند تا بازگشت غیرمنتظره رخ ندهد.
- تأخیر نمونه‌برداری حدود ۲ ثانیه است و آستانه ۶۰ ثانیه‌ای یک **انتخاب مهندسی** است نه معیار علمی خستگی چشم.
- قبل از ادغام، تست دستی هر دو حالت فعال و غیرفعال، مکث دستی، خواب/بیداری سیستم، وقفه واقعی و رفتار اعلان لازم است.
